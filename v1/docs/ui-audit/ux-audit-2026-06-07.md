# UX / UI audit — 2026-06-07

Two-perspective audit of the running app (`localhost:3000`, branch `feat/bank-ai-authoring-ui`)
captured at desktop 1440×900 and mobile 390×844. Screenshots (gitignored) live in
`.audit-fixtures/ux-audit-2026-06-07/`. Conducted by two independent reviewers:

- **New-user** — a non-technical job seeker, first time in the product.
- **Senior designer** — judging against the editorial design system (cream paper / Midnight
  Indigo / rust; Outfit display, mono eyebrows; paper cards; the marketing landing as the
  polish reference).

Plus an orchestrator pass (console/network).

---

## The five themes

1. **Jargon is the #1 new-user barrier.** "Components / Bank / Knowledge / Atomize /
   Strengthen / Articulate / Tailor / JD / verified-draft / confidence" — none map to how a
   job seeker thinks ("resume, experience, jobs, cover letter"). Re-skinning labels fixes most
   P0/P1 confusion without re-architecting. (NU-1, NU-2, NU-3, NU-8, NU-14, NU-15)
2. **No clear primary action.** Toolbars (Studio, bank, opportunities) are walls of near-equal
   solid-dark buttons; "Tailor" even appears twice with a footnote apologizing for the
   duplication. The eye can't find the one true next step. (DS-1, DS-3, DS-9, NU-4, NU-8)
3. **Bank cards are badge-soup with sub-minimum controls.** category + "Unverified draft" +
   "Medium confidence" + a `text-2xs py-0.5` Confirm/Strengthen button all wrap on one row;
   two warning chips at once dilute the warning color; tap target < 44px. (DS-2, DS-16, NU-3)
4. **Demo/seed data alarms a new user.** 718 opportunities they never added, a "99+" red bell,
   onboarding pre-checked "5 of 9", all-zero status filters. Reads as noise/anxiety on first
   run. (NU-9, NU-11, NU-12, DS-7, DS-13)
5. **Design-system drift in the details.** Dashed borders in ~7 non-dropzone surfaces (the spec
   forbids this), bank cards flatter than the landing/dashboard paper cards, a redundant
   floating settings FAB overlapping content, low-contrast mono eyebrows / tertiary ink near
   AA limits. (DS-4, DS-18, DS-11, DS-8) Plus 7 × 404 for missing landing `.mp4` demos + an
   LCP-priority warning (orchestrator).

---

## Fix plan

### A. Clear-cut wins (no product decision needed — safe to implement)
- **A1** Bank card: drop the confidence chip when an entry is an unverified draft (one warning
  signal per card); move/enlarge the Confirm/Strengthen action (≥ `px-2.5 py-1 text-xs`,
  `min-h-8`; full-width footer on mobile). [DS-2, DS-16, NU-3]
- **A2** Replace `border-dashed` with solid `border-rule` in the ~7 non-dropzone surfaces;
  keep dashed only for real file dropzones. [DS-4]
- **A3** Opportunities "Dismissed" status: remove the strikethrough (reads as a bug); use a
  neutral muted chip. [DS-6]
- **A4** Hide zero-count status filter badges (show label only). [DS-7]
- **A5** Surface the "AI won't invent facts" promise on the bank page header / near the draft
  badges (today it only appears inside the Draft dialog). [NU-3, NU-16]
- **A6** Notification bell: calmer tone (system token, cap "9+"), suppress for brand-new
  accounts. [DS-13, NU-11]
- **A7** Landing: fix/remove the 7 missing `.mp4` section demos (404s) + add `priority` to the
  LCP image. [orchestrator]
- **A8** Bank cards: apply `bg-paper` + `shadow-paper-card` to match dashboard/landing depth.
  [DS-18]
- **A9** Standardize one AI glyph (sparkle = generative) across Draft/Strengthen/Tailor. [DS-17]
- **A10** Remove or repurpose the redundant settings FAB (overlaps cards; Settings already in
  nav). [DS-11]

### B. Opinionated / product decisions (need your call)
- **B1 — Vocabulary re-skin** (biggest impact). Rename user-facing labels to outcomes:
  Components/Bank → "Experience" / "Resume content"; "Knowledge" tab → "My Experience";
  spell out "JD" → "job description"; reconsider "Atomize" / "Strengthen" / "Articulate" /
  "Unverified draft" → plainer terms. Keep table/route names internal. [NU-1/2/3/8/14/15]
- **B2 — Primary-action pass on toolbars**: one solid primary per region; demote the rest to
  outline/ghost; segmented controls for view toggles; collapse the duplicate Tailor entry
  point. [DS-1, DS-3, DS-9, NU-4, NU-8]
- **B3 — New-user seed data**: start empty (or clearly label "Sample") for opportunities,
  notifications, and onboarding progress; unify "Opportunities" vs "Review Queue" into one
  Jobs area with an Incoming tab. [NU-9, NU-10, NU-12]
- **B4 — Segment the developer/OSS messaging** (GitHub CTA, BYOK/AGPL/self-host, LaTeX,
  WYSIWYG) out of the consumer flow. [NU-5, NU-6, NU-7, NU-18]

## Full findings

### New-user perspective (NU)

First impression: confident, good-looking landing, but it doesn't plainly say what it does to a
resume; the GitHub CTA + BYOK/AGPL/self-host copy signal "for developers." Inside, the dashboard
onboarding checklist and Studio's numbered empty state are the clearest screens — but the left
nav and the bank are a wall of insider vocabulary where a normal job seeker would give up.

| ID | Sev | Screen | Confusion | Fix |

### Senior-designer perspective (DS)

Overall: the app has clearly absorbed the landing's editorial DNA (cream paper, Outfit, mono
eyebrows, rust accent) and reads as one product family. Settings, Opportunities, and the mobile
bank/dashboard are strongest. Weak spots: toolbars (no primary), bank badge-soup, forbidden
dashed borders, and a too-many-solid-primaries button-hierarchy problem. Contrast mostly safe on
cream but a few mono eyebrows / tertiary-ink lines sit at/below AA. Closing the gap is disciplined
application of existing primitives, not new design.

| ID | Sev | Screen | Issue | Principle | Fix |
|----|-----|--------|-------|-----------|-----|
| DS-1 | P0 | Studio | ~8 competing controls, no primary; "Tailor" duplicated w/ apology footnote. | hierarchy | One primary per region; collapse dup Tailor; cluster undo/redo/history. |
| DS-2 | P1 | Bank cards | Up to 4 chips + action wrap one row; two warning chips at once. | density/color | Split metadata from action; suppress confidence when draft. |
| DS-3 | P1 | Opps/Bank | Too many solid-dark "primary" buttons per toolbar. | hierarchy | One brand primary; segmented view toggle; soft active filter chip. |
| DS-4 | P1 | many | Dashed borders in ~7 non-dropzone surfaces (spec forbids). | consistency | Solid `border-rule`; dashed only for real dropzones. |
| DS-5 | P1 | Draft dialog | Cramped textarea, weak header hierarchy, helper clutter. | spacing | `p-6`, `space-y-4`, display title, `bg-paper` textarea. |
